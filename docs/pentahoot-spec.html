Pentahoot: keputusan produk dan rancangan teknis

PRD dari PM menjelaskan apa yang harus dilihat host, layar publik, dan peserta. Dokumen ini mengunci hal-hal yang belum diatur PRD: identitas peserta, akun host, siklus hidup event, aturan seri, arsitektur realtime, dan model data. Setiap keputusan punya ID supaya bisa dirujuk di tiket dan commit.

01Ringkasan

Pentahoot adalah web game untuk acara internal. Satu event berisi tiga game yang dijalankan host dari laptop dan ditampilkan di proyektor: Pentahoot (voting ala awards dari HP peserta), Tebak Kata (satu soal dengan kotak huruf), dan Tebak Gambar (gambar soal lalu gambar jawaban). Peserta masuk lewat link tanpa install dan tanpa login.

Skala yang dirancang: sampai sekitar 200 peserta per event, beberapa event bisa berjalan bersamaan (misalnya per divisi), satu server. Stack: Laravel 13 + PHP 8.4 di Docker, MySQL server yang sudah ada, Laravel Reverb, Blade + Alpine.js + Laravel Echo, tanpa Redis dan tanpa queue worker.

Soal ditulis di paket soal yang bisa dipakai ulang, lalu disalin ke event setiap kali dimainkan, seperti satu kahoot yang bisa dimainkan berkali-kali. Setiap jenis game punya engine sendiri dengan kontrak yang sama, sehingga game baru bisa ditambah tanpa mengubah game yang sudah ada.

Bagian paling berisiko bukan CRUD, tetapi realtime: countdown yang sinkron di ratusan HP, peserta yang putus-sambung di internet venue yang buruk, suara yang harus ditolak tepat saat waktu habis, dan gambar jawaban yang tidak boleh bocor sebelum Reveal. Rancangan di bagian 08 dibuat khusus untuk empat hal ini.

15Rilis staging dan production

Langkah sekali jalan untuk menyiapkan tiap lingkungan, lalu langkah yang diulang di setiap rilis. Bagian dalam kurung siku, seperti [DOMAIN STAGING], diisi saat server disiapkan. Perintah di bab ini ditulis sebagai acuan urutan; nama service, path, dan flag persisnya dipastikan saat compose.yaml dan workflow CI ditulis di tahap 1, lalu bab ini diperbarui kalau ada yang berbeda.

Staging: disiapkan sekali

  1. 1
    Akses server

    Senior menyiapkan VM (boleh sama dengan production atau terpisah), memasang Docker, membuat user deploy dengan kunci SSH khusus, dan membuka port 80/443.

  2. 2
    Domain dan TLS

    Subdomain [DOMAIN STAGING] diarahkan ke VM. TLS dan reverse proxy mengikuti pola kantor (staging vivace-board memakai Caddy). Proxy wajib meneruskan WebSocket ke container reverb.

  3. 3
    Database

    Di server MySQL yang sudah ada (A9): buat database pentahoot_staging dan user yang hanya punya akses ke database itu. Izinkan koneksi dari jaringan Docker. Catat versi MySQL (O-B).

    -- dijalankan sebagai admin MySQL di server
SELECT VERSION();
CREATE DATABASE pentahoot_staging CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'pentahoot_staging'@'[SUBNET DOCKER]' IDENTIFIED BY '[PASSWORD KUAT]';
GRANT ALL PRIVILEGES ON pentahoot_staging.* TO 'pentahoot_staging'@'[SUBNET DOCKER]';
FLUSH PRIVILEGES;
  4. 4
    GitHub

    Repo di devivace-groups. Environment staging dan production (P5). Secrets: host, user, dan kunci SSH deploy. Cek branch protection (W7).

  5. 5
    Registry image (P1)

    Image disimpan di GitHub Container Registry sebagai paket privat. VM login ke registry dengan token yang hanya bisa membaca.

    # di VM, sekali, sebagai user deploy
echo "[TOKEN READ:PACKAGES]" | docker login ghcr.io -u [USER GITHUB] --password-stdin
  6. 6
    Berkas di server

    Folder deploy hanya berisi compose.yaml dan .env staging (APP_KEY, kunci Reverb, kredensial database). Tidak ada kode sumber, PHP, atau Composer di server; yang dibutuhkan hanya Docker. compose.yaml berasal dari repo dan disalin oleh job deploy setiap kali deploy. .env dibuat langsung di server dan tidak pernah masuk repo (O3).

  7. 7
    Deploy pertama

    Tarik image, jalankan migration, buat super-admin dengan php artisan pentahoot:create-super-admin, jalankan DemoSeeder, lalu smoke test (P4).

    cd [FOLDER DEPLOY]
IMAGE_TAG=[SHA] docker compose pull
docker compose run --rm app php artisan migrate --force
docker compose run --rm app php artisan pentahoot:create-super-admin   # email & password ditanya interaktif
docker compose run --rm app php artisan db:seed --class=DemoSeeder     # staging saja
docker compose up -d
curl -fsS https://[DOMAIN STAGING]/up
  8. 8
    Bukti realtime

    Buka Public View di laptop dan voting dari beberapa HP sungguhan lewat proxy staging (A5). Setelah itu jalankan uji beban F19 dengan dan tanpa Pulse (O5).

    Rollback otomatis

    Kalau smoke test gagal, tag image dikembalikan ke versi sebelumnya lalu docker compose up -d dijalankan lagi. Migration selalu kompatibel dengan versi sebelumnya (W14), jadi rollback tidak perlu membatalkan migration.

Production: setiap rilis versi

  1. 1
    Persetujuan

    Pemilik proyek menyetujui rilis dan nomor versinya (W2, W9). Cek jadwal event: dilarang deploy selama event berlangsung (O2).

  2. 2
    Branch rilis

    Buat release/x.y.z dari develop. Pindahkan [Unreleased] di changelog ke [x.y.z] - YYYY-MM-DD (W10) dan perbarui nomor versi aplikasi.

git checkout -b release/1.1.0

gh run watch                         # tunggu CI hijau (W18)
  3. 3
    CI hijau

    Branch rilis wajib hijau sebelum merge (W18).

  4. 4
    Merge dan tag

    git merge --no-ff ke main, beri tag vx.y.z, push. Lalu back-merge release/x.y.z ke develop dan hapus branch rilis.

    git checkout main && git pull --rebase origin main
git merge --no-ff release/1.1.0
git tag -a v1.1.0 -m "release: v1.1.0"
git push origin main --follow-tags   # memicu build image v1.1.0 + deploy (menunggu persetujuan P5)
git checkout develop && git merge --no-ff release/1.1.0 && git push origin develop
git branch -d release/1.1.0 && git push origin --delete release/1.1.0
  5. 5
    Deploy

    Tag memicu build image vx.y.z. Deploy production menunggu persetujuan di environment GitHub (P5), lalu menjalankan lima perintah yang sama dengan staging dengan IMAGE_TAG=vx.y.z. Rollback: jalankan lagi dengan tag versi sebelumnya.

    # rollback manual kalau diperlukan
cd [FOLDER DEPLOY PRODUCTION]
IMAGE_TAG=v1.0.0 docker compose pull
IMAGE_TAG=v1.0.0 docker compose up -d
curl -fsS https://[DOMAIN PRODUCTION]/up
  6. 6
    Sesudah deploy

    Cek manual singkat dari satu HP dan satu laptop. Salin bagian changelog versi itu ke GitHub Releases.

    gh release create v1.1.0 --title "v1.1.0" --notes-file [BAGIAN CHANGELOG v1.1.0].md
